# 应用图标目录

当前图标：**黑底白色金毛头像线稿**（用户提供的生成图，2026-08-20 定稿；取代 DG 5.8
原拟的「M↓ 符号」方案与同日短暂使用的实照——实照在 16/32px 会糊，线稿高对比不糊）。
源图存本目录 `_source-app-icon.png`（1024×1024）。

## 重新生成（换图标时的唯一正确姿势）

准备一张 ≥1024×1024 的方形 PNG，在仓库根目录执行：

```
pnpm tauri icon path/to/source-1024.png
```

全套图标会写入本目录（含 macOS/Linux/移动端尺寸；Windows 打包只消费下表四个，
多余文件保留不影响）。**手改单个 png 不算换图标**——ico 的多尺寸图层不会跟着变。

## Windows 打包实际消费的文件（与 `tauri.conf.json` 的 `bundle.icon` 一一对应）

| 文件 | 用途 |
|---|---|
| `32x32.png` | 小尺寸位图 |
| `128x128.png` | 常规位图 |
| `128x128@2x.png` | 高 DPI 位图（实际 256x256） |
| `icon.ico` | **Windows 必需**：exe 图标、安装器图标、文件关联图标；内含 16/32/48/64/256 多尺寸 |

## 注意

- 文件关联的图标同样取自 `icon.ico`（bundler 自动关联），`.md` 在资源管理器中的显示
  取决于 ico 的 16×16 / 32×32 图层——高对比线稿在这两档仍可辨认，实照类会糊成色块
  （这正是 2026-08-20 实照方案当天被换掉的原因）。
- **换图标必须先 `cargo clean -p mdnaonao --release` 再 `pnpm tauri build`**：
  图标由 build 脚本编进 exe 资源，而 cargo 不追踪 icons 目录的变化，
  不清缓存的话成品还是旧图标（2026-08-20 实际踩过）。打包后核对四处：
  exe 图标、安装器图标、关联文件图标、任务栏图标。
