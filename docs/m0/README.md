本目录存放 M0 阶段四张任务卡的验证报告。**这些报告是 M0 出口评审的唯一依据**（AI_DEV_GUIDE 第 7 节）——没有报告的任务卡一律视为未完成，无论代码是否已提交。

任务卡定义见 [AI_DEV_GUIDE.md 第 7 节](../../AI_DEV_GUIDE.md)，阶段目标与出口标准见 [DEV_GUIDE.md 9.1](../../DEV_GUIDE.md)，进度状态只在 [DEV_GUIDE.md 9.2](../../DEV_GUIDE.md) 维护（单一事实源，不要在本目录重复记状态）。

## 3. M0 出口评审判定标准（引 DEV_GUIDE 9.1）

> **出口标准原文**：4 项全通过；①②任一不达标则升级为方案变更（PDF 降级系统打印对话框 / 更换渲染内核）并修订 DEV_GUIDE.md。

评审时逐条核对：

| # | 判定项 | 依据 |
|---|---|---|
| 1 | M0-①：主路线（PrintToPdf COM）与兜底 A（CDP 驱动 msedge.exe）**各出一份** A4 PDF，中文不乱码、宽表格完整、长代码块不截断、Mermaid 清晰；记录耗时与失败模式 | DG 9.1 M0 行、任务卡 M0-① DoD |
| 2 | M0-②：`Vditor.preview()` 跑通 test-corpus 全部语料；`outlineRender` 标题树正确；**本地图片方案定案**（asset 协议 vs data URL，含中文/空格/UNC 路径实测）；frontmatter 默认行为查明；CDP 全页长图实测（`captureBeyondViewport: true`，含 >16384px 分页）；裁剪后体积 / 10MB 渲染耗时 / 内存 / 滚动帧率 vs DG 3.2 达标判定；`xss-suite` 全过且 DevTools Network 证明零外网请求 | DG 9.1、任务卡 M0-② DoD、DG 3.2 |
| 3 | M0-③：`write_html` 产物粘贴到**公众号编辑器**与**飞书文档**各一份 8 项样式清单核对表（标题/加粗/列表/引用/代码块/表格/图片占位/链接） | 任务卡 M0-③ DoD、DG 12 v1.1 出口 |
| 4 | M0-④：fileAssociations 装包实测（五扩展名 + 卸载后关联回落，**须在虚拟机或人类确认的测试机执行**）、single-instance 第二实例路由回调、`--action open <file>` 直跑且日志落盘——三条链路各一条通过记录 | 任务卡 M0-④ DoD |
| 5 | 全部依赖冻结为精确版本号（`package.json` / `pnpm-lock.yaml` / `Cargo.lock` / `rust-toolchain.toml`）并回填 DG 4.2 | DG 4.2 |
| 6 | 基准测试机型号确认并回填 DG 11.4；本目录四份报告齐全且判定明确 | DG 11.4、AI_DEV_GUIDE 第 7 节 |

**不达标时的处置**：

- **M0-① 主路线卡点**：自 DG 9.2 将该卡置 🔄 起计 **3 个工作日**（仅计主路线投入，兜底 A 不计入），到期未通即按 AI_DEV_GUIDE 第 9 节格式上报（卡在哪 → 已尝试什么 → 证据 → 选项 A/B/C + 推荐），由人类决定继续或降级为系统打印对话框方案并修订 DEV_GUIDE。
- **M0-② 不达标**：触发渲染内核方案变更评估（备选 markdown-it 自组管线，成本预估见 DG 4.1），同样先上报再改方案——**不要静默改方案**。
- 任何与 AI_DEV_GUIDE 第 3 节"已核验事实库"矛盾的现象：停下、报告证据、等人类确认后同步更新 DEV_GUIDE 与事实库。
