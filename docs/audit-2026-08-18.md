## MPE标杆

以 MPE/VS Code 内置预览为标杆审计 MDNaonao（全部 13 个源文件已通读，MPE 能力经 crossnote 官方仓库核对）。结论：渲染管线的底子不差（代码块语言标签+复制钮、标题锚点、滚动高亮、错误态、加载态均已落地，部分甚至超出 MPE），但存在两大系统性缺口：一是「设置有状态、无消费者」——zoom/readingFontSize/codeWrap 三个设置项在 settings store 里完整持久化，却没有任何 DOM 消费它们；二是「浏览器默认行为未接管」——链接点击（外链会把整个 WebView 导航走）、文档内查找（按钮已画在顶栏但无实现）、键盘翻页、主题按钮全部处于未接线状态。与 MPE 差距最直观的两处体验：文件变更刷新时整页白闪+滚动位置跳动（innerHTML 先清空、settled 后才恢复 scrollTop），以及重开文件不记滚动位置（FR-16 的 IPC 已定义但前端从不调用）。排版侧最大缺口是 GitHub alerts（> [!NOTE] 五色告警块，MPE/crossnote 已支持）会裸露成普通引用。共 24 项，2 blocker / 12 major / 6 minor / 4 polish。

**[blocker] 链接点击行为完全未接管，点外链会把整个应用导航走**

src/styles/markdown.css:249-257 只定义了链接样式；src/App.tsx 与 src/render/preview.ts 全文无任何 a 标签 click 拦截，src/services/ipc.ts 也没有打开系统浏览器的命令封装。Tauri WebView 里点击 http(s) 外链的默认行为是整个 WebView 就地导航——阅读器瞬间变成一个回不来的残废浏览器。MPE/VS Code 预览：外链一律交系统默认浏览器，预览面板本身永不被导航。

**[blocker] 文档内查找（Ctrl+F）完全缺失，但查找按钮已经画在顶栏上**

App.tsx:640 的查找 IconButton 无 onClick（现状是个死按钮）；键盘处理（App.tsx:1347-1382）只绑了 F5/Ctrl+O/Ctrl+Alt+O/Ctrl+B，无 Ctrl+F；WebView2 不提供内置查找 UI。MPE/VS Code 预览内 Ctrl+F 有完整查找条：全部命中高亮+计数、Enter/Shift+Enter 逐个导航、Esc 关闭。对纯阅读器这是底线功能。

**[major] 相对路径 .md 链接应在本应用内打开，现状点了会导航到 404**

MPE 点击 [x](./other.md) 直接打开该文件的预览，且支持 ./other.md#锚点 定位。本项目无处理：点击后 WebView 按相对 URL 导航 → 白屏/404，应用状态丢失。App.tsx:68 已有 SUPPORTED_EXTENSIONS 常量，fileSession.openPath 链路现成。

**[major] 缩放是死数据：有状态、有持久化、状态栏有显示，但不作用于任何 DOM**

settings.ts:126-134 的 setZoom/resetZoom（90-150 钳位）完整实现并持久化；App.tsx:1101-1108 状态栏按钮只展示 `${zoom}%` 且无 onClick；grep 全 src 无任何地方把 zoom 应用到样式；无 Ctrl+=/−/0 快捷键、无 Ctrl+滚轮。MPE/VS Code 预览缩放即调即生效。

**[major] readingFontSize 设置未接线，markdown.css 写死 16px**

markdown.css:15-16 硬编码 font-size:16px/line-height:28px；settings.ts:119-124 的 setReadingFontSize（14-20 钳位）无任何消费者。标题字阶（h1 24px…h4-h6 16px，markdown.css:47-73）也全是绝对值，字号一变层级比例就崩。

**[major] codeWrap（代码折行）设置未接线**

markdown.css:189-202 固定 white-space:pre + overflow-x:auto，注释自陈「设置项『代码折行』后续可切」；settings.codeWrap 已持久化但无消费者。MPE 对长行代码提供折行控制，读日志/长命令类文档时横向滚动很伤阅读。

**[major] GitHub alerts（> [!NOTE] 等五种）不渲染，标记字面量裸露**

lute/Vditor 管线不识别该语法，markdown.css 无对应样式：现状 > [!NOTE] 按普通 blockquote 显示且「[!NOTE]」文本裸露在正文里。MPE/crossnote 已支持 admonitions/callouts（官方 CHANGELOG 载明），GitHub 上的 README 大量使用此语法，这是当下阅读器的事实标准。

**[major] 表格滚动包裹只覆盖顶层，嵌套在列表/引用里的宽表格会引发整页横滚**

markdown.css:216-221 仅对 .md-content > table 兜底 display:block+overflow-x:auto；嵌在 li/blockquote 里的宽表格（width:max-content，markdown.css:210-212）不命中该选择器，横向溢出会转嫁给阅读区 main（overflow-y:auto 会把 overflow-x 计算成 auto），出现整个阅读区横向滚动条。MPE 的表格始终在自身范围内解决滚动。

**[major] 文件变更刷新会白闪+滚动位置跳动，与 MPE 的『纹丝不动』差距最直观**

preview.ts:986 一进 renderMarkdown 就整体覆写 container.innerHTML → 旧内容立即清空、滚动高度塌缩、scrollTop 被钳到 0；App.tsx:1423-1425 要等 waitForRenderSettled（最长 8 秒，preview.ts:91）后才恢复 keepTop；期间 Mermaid/KaTeX 异步落地还会让版面反复跳。MPE/VS Code 预览：编辑保存后预览无白屏、无闪烁、位置不动。

**[major] 重开文件不记滚动位置：FR-16 的 IPC 已定义，前端从不调用**

ipc.ts:117-121 的 setScrollAnchor(path, anchor) 已封装（Rust 侧契约也已列入），但 App.tsx 全文无调用；任何文件重开永远回顶部。MPE 预览重开/切回保持阅读位置。对『最近列表』为核心交互的阅读器，这是高频痛点。

**[major] system 主题只在启动时解析一次，运行中系统切深浅不跟随；主题按钮本身也没接线**

settings.ts:56-66 applyThemeAttribute 用一次性 matchMedia 查询，未挂 change 监听；App.tsx:1109-1116 状态栏月亮按钮无 onClick。MPE/VS Code 随系统/编辑器主题即时切换。现状用户白天开着应用到晚上，界面永远停在启动时的模式。

**[major] 主题切换一旦接线，会把阅读位置甩回顶部**

渲染 effect 依赖含 resolvedTheme（App.tsx:1443），主题变化触发全量重渲染；而 keepTop 仅在 silentRefresh 时保留（App.tsx:1396），主题切换场景下为 0 → 归顶。MPE 主题切换内容位置不动。注：hljs github/github-dark 与 Mermaid 主题已随 resolvedTheme 正确联动（preview.ts:303-311、1003），这部分已对齐，只差滚动保持。

**[major] PgDn/PgUp/Space/Home/End 翻页大概率无效**

滚动容器是内部 overflow-y 的 main（App.tsx:942-946），html/body overflow:hidden（index.css:54-59）；main 无 tabindex，点击正文后焦点落在 body，按键找不到可滚动目标。MPE/VS Code 预览面板键盘翻页开箱即用。长文阅读场景键盘翻页是刚需。

**[major] 属性卡片『万事俱备只欠 UI』，现状 frontmatter 信息凭空消失**

stripFrontmatter（preview.ts:202-249）已剥离并解析、setRendered 已入 store、markdown.css:351-368 的 .md-frontmatter 样式已写好、settings.frontmatterDisplay 默认 "card"——但 App.tsx 渲染树没有任何 frontmatter 消费者。含 YAML 头的文档现在头部元信息直接蒸发，比 MPE 原样显示 YAML 还糟（作者写的 title/date/tags 读者完全看不见）。

**[minor] 正文内 #锚点点击与大纲跳转行为不一致，且 id 改写可能弄断作者手写锚点**

标题锚点（.vditor-anchor）与正文 [](#id) 走浏览器默认瞬跳：无 HEADING_JUMP_PADDING 16px 留白（App.tsx:73）、无 250ms 平滑滚动，落点贴死顶沿，与大纲跳转手感割裂。另外 buildOutline 去重会改写重复标题的 id（preview.ts:706-734），作者在正文里手写引用旧 id 的锚点会失效。

**[minor] [TOC] 指令被显式关闭，长文开头无法就地生成目录**

preview.ts:296 markdown.toc:false（注释理由：导出模板自己生成，正文不插）。MPE 支持 [TOC] 就地渲染目录树；GitHub wiki/长 README 常用。本项目有大纲面板兜底，故不算刚需，但含 [TOC] 的文档现在会留下一行裸文本。

**[minor] <details>/<summary> 折叠块无样式且透传未验证**

技术文档高频使用（GitHub 折叠段落事实标准）；MPE 完整渲染 raw HTML。DOMPurify 配置（preview.ts:58-66）不禁 details，但 lute markdown.sanitize:true 下 raw HTML 的透传保真从未验证，markdown.css 也没有 details/summary 的任何规则（无 cursor:pointer、无 marker 样式、无展开内容缩进）。

**[minor] :smile: 短代码渲染未验证、未显式配置**

MPE 支持 emoji shortcodes（crossnote 官方特性列表载明）。本项目 buildPreviewOptions（preview.ts:281-301）未显式设置 emoji 相关选项，md2html 路径下 lute 的 emoji 行为是默认值，从未用 fixture 验证过；preview.ts:368 有『应用自身资源（emoji 等）』的路径放行注释但无对应资源。

**[minor] 化学式扩展 mhchem 被静默 stub 掉，\ce{} 公式无声失败**

preview.ts:135-140 刻意用 meta 占位骗过 addScript，让 mhchem.min.js 缺失不阻塞主流程——设计是对的，但副作用是含 \ce{H2O} 的文档公式静默渲染失败且无任何提示。MPE 的 KaTeX 自带 mhchem。

**[minor] Mermaid 语法错误时的呈现未定义、未样式化**

图语法写错时 Vditor/Mermaid 的输出（裸英文 error 文本或残缺 SVG）未经任何接管；waitForRenderSettled 超时仅 console.warn（preview.ts:934-936），用户侧无感知。MPE 在图位置就地显示可读的错误信息块。

**[minor] 图片灯箱已埋标记未实现（MPE 没有，属超越项但已在规划内）**

preview.ts:507 已给本地图片打 data-preview-image="true" 并注明『供阅读区做灯箱事件委托（DG 6.4-4）』，但 App.tsx 无对应委托与灯箱组件——现状点击图片无任何反应。MPE/VS Code 预览点图也无反应，此项属加分，但标记已埋说明是既定规划。

**[polish] 外链图片逐张点击加载太费手，缺『本篇全部加载』**

红线 4 的占位块设计（preview.ts:423-456）安全立场正确，但一篇几十张外链图的文章要点几十次；MPE 直接显示外链图片零摩擦。差距可以用一次性授权收窄而不破红线。

**[polish] 链接 hover 无目标提示，用户不知道点了会去哪**

## 顺手度

对 MDNaonao 做了全量「顺手度」审查（App.tsx / uiState / recentFiles / settings / fileSession / preview.ts / index.css / markdown.css / lib.rs / main.rs / tauri.conf.json 全部通读）。结论：交互硬伤集中在两大类。第一类是「WebView2 默认行为未驯服」——浏览器快捷键（Ctrl+R/P/F、Alt+方向键）全部裸奔、正文外链一点就把整个应用导航去网站、Ctrl+滚轮缩放的是整个窗口 UI，这三条任何一条被用户撞上都是「这不是桌面软件」级别的破功。第二类是大面积「状态层/后端已就绪、UI 从未接线」的断链：Esc 语义链（closeTopLayer 是死代码）、查找、置顶/移除、失效路径灰显（missingPaths 永远为空）、滚动位置记忆（FR-16）、file-removed 事件（后端在发、前端没订阅）、窗口几何记忆（TODO 未做）、左栏/大纲拖宽（且 uiState 与 tokens 的宽度常量互相矛盾：260/200-360 vs 280/264-420）、zoom/字号对渲染零作用——每一条都是文档承诺过、代码搭了一半、点了没反应的「死链路」。另有一批一小时能修的毛刺：死按钮共 6 个（查找/导出/分享/更多/zoom%/主题月亮钮，其中主题切换后端明明已实现）、点击已打开文件会整篇重开归零滚动、代码块「复制」按钮文字会被选中复制走、锚点/脚注瞬移绕过平滑滚动还污染 history、两次大纲跳转动画互相打架、键盘无法滚动阅读区（PageDown 无目标）等。逐条已注明惯例依据、现状代码行号、修法与工作量。

滚动容器是 <main>（App.tsx:942-946），无 tabindex 不可聚焦；html/body overflow:hidden（index.css:54-59）掐掉了文档级滚动。键盘滚动事件的目标是焦点元素（body）→ 文档滚动器 → 不可滚，于是翻页键全部落空，除非用户恰好 Tab 到正文内某个按钮。惯例：阅读器打开文档后 PageDown/空格/Home/End 即刻可用，这是「阅读体验优先」的底线。

**[major] 查找功能整体缺位：顶栏放着一个死的查找按钮，Ctrl+F 漏给浏览器**

uiState 里 findOpen/findQuery/findIndex/findTotal/openFind/closeFind（uiState.ts:23-27, 85-99）全部就绪但零消费；顶栏查找钮（App.tsx:640-642）无 onClick；Ctrl+F 未接管、现在弹的是 Edge 原生查找条。DG 6.5 把 Ctrl+F 文档内查找标为 M1 且注明「阅读器通用语义，不可挪用」。查找是对标 MPE 的基本盘。

**[major] 置顶/移除/在资源管理器定位：store 与 IPC 全都写好了，但界面上没有任何入口**

recentFiles.togglePin/remove（recentFiles.ts:130-148）、ipc.revealInExplorer（ipc.ts:68）均无调用方；RecentRow（App.tsx:701-720）整行只有一个打开动作，无 hover 按钮、无自绘右键菜单。DG FR-03 承诺右键菜单含置顶/移除/定位。现状用户对条目右键得到 WebView 默认菜单，长按/hover 也没有任何操作暴露——分组里的「置顶」组永远不可能有内容。

**[major] 失效路径灰显是死链路：missingPaths 永远为空数组，点失效条目直接摔进全屏错误页**

recentFiles.setMissingPaths（recentFiles.ts:166）全仓库无调用者，也没有任何后端探测被触发——RecentRow 的 missing 灰显（App.tsx:711）一次都不会生效。点已删除文件的条目 → openPath 失败 → 全屏错误页，页里只有「重试/打开文件」（App.tsx:889-914），没有 DG 6.6 承诺的「从列表移除/重新定位」，用户清不掉死条目（移除入口本来就没有，见上条）。惯例：VS Code 最近列表对失效项灰显并提供移除。

**[major] 打开中的文件被外部删除/重命名，界面装聋：后端在发 file-removed，前端根本没订阅**

files.rs:49 定义并在 files.rs:485 emit "file-removed"，但 ipc.ts 只有 EVENT_FILE_CHANGED 的订阅——文件被删后 UI 纹丝不动，直到用户 F5 才撞见错误页且正文被整个替换。fileSession.missing/setMissing（fileSession.ts:88, 253）也无消费者，DG 6.6 的「顶栏下警示条 + 保留正文」没有实现。惯例：VS Code/MPE 文件被删时保留已渲染内容 + 非模态警示，不清空用户正在读的东西。

**[major] FR-16 滚动位置记忆完全未接线：重开任何文件都回到顶部**

ScrollAnchor 类型、set_scroll_anchor 命令、fileSession.scrollAnchor、recentFiles.updateScrollAnchor（recentFiles.ts:150-160）四层全部就绪，但没有任何 scroll 监听写入、打开时也从不恢复——全是死代码。惯例：阅读器（MPE 切回 tab、Typora 重开文件）都回到上次位置；对长文档阅读器这是核心顺手度。

**[major] 窗口大小/位置/最大化不记忆：每次启动都是 1200x800 居中**

settings.rs:68 有 WindowGeometry 结构体，lib.rs:44-47 的 TODO(M1) 写明「恢复窗口几何」未做；tauri.conf.json:18-22 固定 center:true + 1200x800。用户每次调好窗口，重启全部作废。惯例：Windows 桌面应用记住几何+最大化态+所在显示器，异常坐标（显示器拔掉）回落主屏居中——settings.rs 注释里自己也是这么承诺的。

**[major] 左栏/大纲宽度不可拖，且两处宽度常量互相矛盾，改码代理会各信一边**

DG 5.2 承诺左栏 264-420px 可拖、大纲 300-520px 可拖。现状：两栏都是固定 Token（tokens.css:120 --md-sidebar-w:280px、:124 --md-outline-w:300px），uiState.setSidebarWidth 是死代码；更糟的是 uiState.ts:12-14 的常量是 260/200-360，与 tokens/DG 的 280/264-420 直接冲突——这属于会引发后续错误实现的文档-代码分裂。

**[major] 6 个死按钮：查找/导出/分享/更多/zoom%/主题月亮钮——其中主题切换的后端逻辑明明已经写完**

顶栏查找、导出、分享、更多四个图标钮（App.tsx:640-658）无 onClick；状态栏 zoom%（App.tsx:1101-1108）与月亮钮（App.tsx:1109-1116）同样无 onClick。它们 hover 有背景反馈、看起来完全可点，点了却无任何事发生——IconButton 注释说「未实现不传 onClick」是自觉决定，但惯例是：不可用的控件必须 disabled+降透明或干脆隐藏，「看起来能点、点了没反应」是死按钮反模式。特别是主题切换：settings.setTheme/applyThemeAttribute（settings.ts:110, 56-66）已完整实现，只差把月亮钮接上这一根线。

**[minor] 点击当前已打开的文件 = 整篇重新读盘重渲染，滚动位置归零**

RecentRow onClick 直调 openPath（App.tsx:709），无 selected 判断；openPath 先 reset 会话再读盘（fileSession.ts:205-208），silent=false 使渲染后 scrollTop 置 0（App.tsx:1396）。用户想「确认一下我在读哪个」点了一下当前条目，正文闪一次、滚动位置丢失。双击则执行两次 openPath（连点竞态有 loadSequence 兜底不出错，但多读一次盘）。惯例：点击已打开项 no-op（VS Code/浏览器 tab 均如此）。

**[minor] 同一文件不同大小写/分隔符会在最近列表里出现两行，且两行同时高亮**

touch 去重用 item.path !== file.path 精确比较（recentFiles.ts:124），而选中高亮用大小写不敏感的 samePath（App.tsx:105-112）——Windows 路径大小写不敏感，资源管理器双击（shell 传参）与 Ctrl+O 对话框回传的同一文件路径大小写/分隔符可能不同，结果是重复条目 + 双高亮。recentFiles 里明明已有 baselineKey 归一化函数（recentFiles.ts:32-34）却没用在去重上。

**[minor] 过滤框无清空按钮、无 Ctrl+Shift+F 聚焦捷径，分组折叠态会被过滤/折叠侧栏悄悄重置**

**[minor] 左栏列表键盘不可导航：↑↓ Enter 无效，Tab 要逐行按几十次才能穿过列表**

每个文件行/分组头都是独立 button，Tab 顺序=顶栏图标钮→搜索框→逐行所有条目→大纲逐行——列表无 roving tabindex，↑↓/Home/End 无处理。惯例（VS Code、资源管理器、所有桌面列表）：列表整体一个 Tab 停靠点，内部方向键移动、Enter 打开、Tab 一次跳出。DG 6.7 也承诺「全部功能键盘可达」。

**[minor] 拖选代码附近的正文，粘贴出来混着「python 复制」——代码块工具条文字可被选中**

index.css:80-83 把 [data-reading-root] 下所有元素放开为 user-select:text，而 enhanceCodeBlocks 注入的语言标签与复制按钮（preview.ts:585-621）就挂在正文 DOM 里——跨代码块拖选或 Ctrl+A 复制，剪贴板里会夹进「python」「复制/已复制」这类 UI 文字。统计字数时特意在增强前取 textContent（preview.ts:992 注释），说明作者意识到了污染问题，但漏了选中复制这条路。惯例：内容区内的 UI chrome 一律 user-select:none。

**[minor] 标题旁锚点与脚注是原生 <a href="#id">：瞬移绕过平滑滚动、还往 history 塞记录**

vditor-anchor（markdown.css:372 有样式、preview.ts:723-729 维护其 href）与脚注引用点击后走浏览器默认锚点导航：瞬间跳转（违反「阅读区唯一允许的滚动动画是大纲 250ms」的自家军规）、URL 加 #hash 并压入 history——之后 Alt+←（未拦截）会在锚点间「后退」，行为极其诡异；跳转也不触发大纲高亮同步（suppressActiveSync 逻辑被绕开）。

**[minor] 快速连点两个大纲标题，两个滚动动画同时抢 scrollTop，来回抖 250ms**

smoothScrollTo（App.tsx:282-303）每次调用起一个独立 rAF 循环，无取消令牌——前一个动画未完成时点第二个标题，两个循环交替写 scrollTop 直到先者结束；动画期间用户滚轮输入也会被 rAF 每帧覆盖（250ms 内滚轮失灵）。惯例：新滚动指令/用户输入立即终止进行中的程序化滚动。

**[minor] 点大纲最后一项后，随手一滚高亮就回跳到上一个标题**

IntersectionObserver 判定带 rootMargin "0px 0px -70% 0px"（preview.ts:779）：只有进入视口上部 30% 的标题才算 active。文档末尾的标题若因内容不足滚不到上部 30% 区域，则永远不会被 IO 判中——jumpToHeading 手动置的高亮（App.tsx:1245）在 320ms 抑制期后被 IO 的回填覆盖回上一个标题。用户视角：「我明明点了最后一章，高亮却停在倒数第二章」。MPE 的处理是滚动到底时强制高亮最后一项。

**[minor] 任务栏与 Alt-Tab 永远显示「MDNaonao」，不带当前文件名**

打开文档后从不调用 window.setTitle，tauri.conf.json 的 title 固定为 MDNaonao——多窗口切换/任务栏 hover 无法分辨在读什么。惯例：文档型应用标题为「文件名 - 应用名」（记事本、Word、Typora、VS Code 全部如此）。

**[minor] 拖入不支持的文件类型零反馈：遮罩不出现、松手也静默**

onDragDrop enter 时 payload.paths.some(isSupportedPath) 为假则不显遮罩（App.tsx:1318-1321），drop 找不到支持的路径就默默 return（App.tsx:1326-1331）。用户拖一个 .txt/.docx 进来毫无表示，会以为应用卡死或拖拽功能坏了。惯例：拖入不支持格式时给「禁止」视觉（遮罩变灰 + 文案「仅支持 Markdown 文件」）。

**[minor] 系统深浅色运行中切换时，代码高亮与 Mermaid 主题不跟随，出现深浅错配**

applyThemeAttribute 只在 load/setTheme 时读一次 matchMedia（settings.ts:56-66），没有 change 监听——theme=system 下用户切换 Windows 深浅色，CSS 变量层靠 prefers-color-scheme 能变，但 store 的 resolvedTheme 停留旧值，而 hljs 主题（github vs github-dark）与 Mermaid 主题是按 resolvedTheme 参数渲染进 DOM 的（preview.ts:303-311, 1001-1003）→ 界面变浅色、代码块还是深色底。惯例：跟随系统 = 实时跟随。

**[minor] 窄窗口无自适应：800px 最小宽下左栏+大纲挤得正文只剩约 220px**

DG 5.2 承诺「窗口宽 <1024px 自动折叠左栏（本次会话内用户手动展开后不再强制）」；现状无任何 resize 监听联动，minWidth 800 时 280(左栏)+300(大纲)+边框留白后正文可用宽约 200-220px，一行只能排十几个字。折叠态也不是 DG 承诺的 56px 图标栏，而是整栏消失（App.tsx:1478）。

**[polish] 大文件「分段渲染」提示条未实现：打开 5MB+ 文件只见一行 spinner，无任何解释**

fileSession.isLarge/partialRender（fileSession.ts:85-86, 241-243）状态齐全，但 App.tsx 从不读 partialRender——DG 6.6 承诺的「顶部细提示条：大文件已启用分段渲染」不存在。大文件渲染 settle 可长达 8s（preview.ts:91），期间用户没有「为什么慢、慢到哪了」的任何线索。

**[polish] 切换文档的 loading 期间旧文正文原地陈列，链接还能点**

openPath 置 phase=loading，但 md-content 容器常驻且只在 empty/error 时 hidden（App.tsx:959-975）——旧文档 DOM 保留到新渲染写入为止，慢盘/大文件时出现「顶部一行 spinner + 下面还是上一篇」的并存态数秒，期间旧文里的复制按钮、链接均可交互。惯例：切换即给明确的过渡态（内容降透明或即时清空）。

**[polish] 无 React ErrorBoundary：任何组件抛错 = 整窗白屏无出路**

main.tsx:19-23 直接 render <App/>，全树无错误边界；渲染管线的错误有 setRenderError 兜底，但组件层任何未捕获异常（例如异常数据进 OutlineRow 递归）会让 React 卸载整树——用户面对纯白窗口，只能任务管理器杀进程。惯例：桌面应用顶层必有崩溃兜底页（错误信息+重新加载按钮+日志路径）。
