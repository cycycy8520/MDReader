# GBK 编码验收语料

> **本文件是源文件，编码为 UTF-8，不能直接当作 GBK 语料使用。**
> 请按 `test-corpus/README.md` 中"GBK 语料的生成与注意事项"一节的命令，把本文件转码为 `gbk.md` 后再做验收。
> 转码后的 `gbk.md` 必须满足三个条件：① 无 BOM；② 按 UTF-8 解码会失败或出现乱码；③ 按代码页 936 解码后与本文件内容逐字相同。

本语料只使用 GBK 字符集覆盖得到的字符：常用汉字、ASCII、以及 GB2312 符号区的中文标点。**请勿在本文件中加入 Emoji、生僻汉字、日文假名、韩文或任何 GBK 无法表示的字符**，否则转码会丢字或抛异常，语料本身就失去了意义。

## 3. 列表

- 编码优先级：优先按 UTF-8 解码
- 解码失败时按 GBK 兜底解码
- 状态栏必须显示实际使用的编码
- 带字节顺序标记的 UTF-8 文件需去除标记后再渲染

1. 读取文件字节
2. 判断是否存在字节顺序标记
3. 尝试 UTF-8 解码
4. 失败则按代码页 936 解码
5. 渲染并在状态栏显示编码名称

## 5. 代码块（注释为中文）

```rust
// 编码检测：UTF-8 优先，失败按代码页 936 兜底
pub fn decode_markdown(bytes: &[u8]) -> (String, Encoding) {
    let body = strip_bom(bytes);
    match std::str::from_utf8(body) {
        Ok(text) => (text.to_owned(), Encoding::Utf8),
        Err(_) => {
            // 注意：此处不能用有损解码，乱码会被误认为正常内容
            let (text, _, had_errors) = encoding_rs::GBK.decode(body);
            if had_errors {
                tracing::warn!("按 GBK 解码时出现替换字符，文件可能是其他编码");
            }
            (text.into_owned(), Encoding::Gbk)
        }
    }
}
```

## 7. 验收要点

1. 打开 `gbk.md` 后，正文中的中文与标点全部正确显示，无问号、无方框、无替换字符。
2. 状态栏显示的编码为 GBK（而不是 UTF-8）。
3. 大纲面板中的中文标题正确显示且可跳转。
4. 导出为网页后，中文仍然正确（导出产物应统一为 UTF-8 并带正确的字符集声明）。
5. 导出为便携文档后，中文字体嵌入正确、无缺字。
6. 复制正文到剪贴板后，粘贴到其他程序中文不乱码。
